# 00. 주어진 상황


## 00.1. 프로젝트 개요
### 00.1.1 기획 서비스 개요 
TRUVE는 뮤지컬 예매, 공연 정보 탐색, 배우와의 소통을 하나의 플랫폼으로 통합하는 서비스입니다.

기존 티켓팅 플랫폼은 오픈 시점의 트래픽 집중에 반복적으로 불안정한 모습을 보이고, 매크로와 다계정 등 비정상 접근에 대한 방어가 부족해 사용자가 공정한 환경에서 예매하고 있다는 신뢰를 갖기 어렵습니다. 또한 티켓 구매는 티켓팅 사이트에서, 캐스팅이나 후기 같은 정보 탐색은 커뮤니티에서, 배우와의 소통은 또 다른 팬 플랫폼에서 이루어지면서 관람 전후의 경험이 분절되어 있습니다.

TRUVE는 예매 안정성과 공정성을 제품의 핵심 가치로 두고, 공연 정보 탐색과 배우 소통 기능을 결합하여 뮤지컬 관람의 전 과정을 하나의 흐름으로 연결합니다.

### 00.1.2 프로젝트 목표
Traffic-Master: AI 기반 대규모 티켓팅 플랫폼

• 핵심 가치
  - 뚫으려는 AI 매크로와 막으려는 AI 방패의 대규모 트래픽 전쟁

• 주요 기술 키워드
  - Extreme Concurrency(동시성 제어), In-memory 컴퓨팅, Canvas/WebGL 좌석 렌더링, 생성형 보안 퀴즈(VQA), KEDA 기반 예측형 오토스케일링, etc

• 목표
  - 15,000석 규모의 트래픽 폭주 상황을 기술적으로 제어하고 매크로를 능동적으로 차단

### 00.1.3 프로젝트 운영구조
- PM/PD, Front/backend, 보안, AI, cloud infra 총 5개 기능 파트로 구성
- 각 기능 파트들을 프로젝트 목표를 구현하기 위해 각자 역할을 다함
- 본 문서 작성 파트는 AI 파트
- AI와 보안의 경우 AI 봇 탐지라는 영역에서 업무가 중첩
- 현재 기획 상으로는 AI는 CAPTCHA만 진행
- 보안 파트는 CAPTCHA 외 영역에서 봇 탐지하는 모델 운영할 계획

### 00.1.4 홈페이지 예매 서비스 플로우
![alt text](../assets/flow.png)
1. **홈/목록**: 공연 리스트 확인 및 특정 공연 선택
2. **공연 상세**: 공연 정보 확인 후 [예매하기] 버튼 클릭
3. **인증/로그인**: (팝업) 비회원 또는 회원 로그인 확인
4. **날짜/회차 선택**: 캘린더에서 날짜와 공연 시간 선택
5. **좌석 선택 (핵심)**: 
   - 미니맵을 통한 구역 선택 -> 실제 좌석 배치도에서 개별 좌석 선택
   - 좌석 등급별 색상 구분 (이미지 우측 하단 참고)
6. **결제/완료**: 최종 가격 확인 및 결제 수단 선택

## 00.2. AI 파트 기획
1. AI 파트 업무
- CAPTCHA 모듈 만들어 예매 서비스 플로우 과정에 적용
2. AI 모듈 구성
- 1인당 각 모듈 하나씩 맡아서 개발
2.1. VQA
VQA는 아래 두 가지 모듈로 구성 후, 테스트 하여 잠정적인 평가기준인 LLM 오답률/사람 정답률을 가지고 보다 나은 모듈을 사용할 것
    - Image VQA
    - Illusion VQA
VQA 단에서도 여력이 된다면 마우스 trajectory 데이터 가지고 feature 뽑아 봇탐지하는 모델 구현할 것
2.2. mouse quiz
- 마우스를 움직이는 퀴즈 출제
- 문제를 해결하는 과정에서 마우스 trajectory data 수집하여 features 만들어, 봇 탐지 모델 설계 후 봇 판별할 것

3. 고려사항
- 각 모듈은 프로젝트의 목적인 15,000 트래픽에서 버티고 latency가 길지 않고 서비스 제공이 원활해야 함
- 비용
    비용적인 측면 또한 고려해야함
    mouse trajectory 수집시 Redis, Kafka를 쓸 것으로 보이나 각 모듈 안에서 데이터 사용 및 모델 돌리고 폐기하는 방향 고려
- 각 모듈은 MSA로 독립적으로 운영할 것

4. 정책
- 각 모듈을 만들고 어떤 곳에서 어느 접속자 대상으로 CAPTCHA 진행할 지 결정할 수 있는 정책 실험 계획도 필수
