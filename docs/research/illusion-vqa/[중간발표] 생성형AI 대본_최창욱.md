1 페이지

생성형 AI 파트에 대해서 말씀드리겠습니다
봇 침투를 방어하기 위한 기본적인 AI 모듈 운영 구조는 여러 모델을 엮어 최대한 다각도로 방어하기 위한 목적으로 구성하였습니다
Google의 reCAPTCHA 같은 기존의 VQA는 LLM 등장 전부터 널리 쓰이던 봇탐지 솔루션입니다. 3x3 칸의 이미지 타일 중에서 버스, 자전거가 있는 칸을 찍으라는 reCAPTCHA를 요즘에는 잘 보지 못하는 걸 느끼셨나요? LLM의 등장으로 기존의 reCAPTCHA 시스템은 봇이 쉽게 풀 수 있게 되었습니다. 봇 탐지가 잘 안되는 겁니다
그래서 다각도로 봇을 탐지하지 하기 위해 각 봇 탐지 Layer 마다 특정 영역에서 특화된 방어 모듈을 설정했습니다. 저희가 채택한 세가지 레이어는 이미지 추론 문제, LLM의 취약 영역을 결합한 문제, 자연스런 마우스 움직임을 테스트하는 문제입니다.
첫 번째 이미지 추론 문제는, 요즘 네이버 로그인시 영수증 보여주면서 구매한 소고기의 단가를 입력하라는 식의 사진의 텍스트를 읽고 한 번 더 생각해서 답을 해야하는 이미지 추론입니다
두 번째 LLM 취약 영역을 결합한 문제는 LLM의 오답률이 높은 문제들로 구성한 문제입니다
마지막 자연스러운 마우스 움직임 테스트는 봇의 경우 마우스 움직임을 잘 보이지 못하니 그걸 테스트 하는 문제입니다

다만, 말씀 드린 문제 유형은 총 3가지이지만, 유저 테스트가 너무 많으면 이용자 불편을 초래하기에 VQA의 유형인 이미지 추론과 LLM 취약 영역 결합 문제는 자체 테스트 결과 더 우수한 모듈을 하나 골라 사용할 것입니다저희가 구상 중인 AI 모듈 상의 유저 움직임은 다음과 같습니다
예매 버튼을 누르기 전의 유저 세션 데이터로 트래픽 분석을 하여 봇으로 판정되는 경우에는 차단을 하고 아닌 경우에는 대기열로 유저를 진입시킵니다. 그리고 나서 VQA 문제를 풀게 하고 문제를 맞추면 좌석 선택으로 넘기고, 오답이 2번 이상이거나 봇으로 의심이 되면 마우스를 움직이는 Puzzle Quiz로 보냅니다

이게 대략적인 AI 모듈 운영 흐름이고 다음에는 각 모듈에 대해 하나씩 말씀드리겠습니다

2페이지(Illusion & cognition VQA)

LLM 취약 영역을 결합한 문제인 Illusion VQA에 대해 말씀드리겠습니다.
설계 원칙은 간단합니다. 사람은 직관적으로 풀 수 있고, LLM은 풀기 어려워야 한다. 이 두 조건을 동시에 만족해야 합니다.
이걸 위해 25년도에 나온 두 논문을 참고했습니다.
첫 번째는 IllusionCAPTCHA입니다. 베이스 이미지 위에 착시를 입혀서 VLM이 표면에 보이는 장면에 혼란을 겪게 만드는 방식입니다. 사람 눈은 착시를 뚫고 실제 사물을 인식하지만, AI는 착시에 속습니다.
두 번째는 COGNITION 논문입니다. VLM이 공간 추론 문제에서 정답률이 20% 이하라는 걸 실험으로 보여줬는데, 반대로 사람은 80% 이상 맞춥니다. 이 차이를 활용했습니다.
이 두 가지를 합쳐서 이중 방어 구조를 만들었습니다. 공간 추론 문제 자체가 LLM에게 어렵고, 거기에 착시 이미지까지 얹으면 더 어려워지는 구조입니다.

그럼 실제 구현 흐름을 보여드리겠습니다.
크게 네 단계입니다.
1단계, 데이터 준비입니다. HuggingFace의 fruits-360 데이터셋에서 과일 9종을 추출합니다. 흰 배경에 사물 하나만 찍힌 이미지라 착시 효과를 입히기 좋습니다.
2단계, 착시 생성입니다. 두 가지 방법을 병행합니다. 하나는 로컬에서 직접 색 변환, 무늬, 테두리 블렌딩 같은 처리를 순서대로 쌓는 방식이고, 다른 하나는 Replicate의 illusion-diffusion-hq 모델을 씁니다. 이게 아까 디퓨전 모델 쓰냐고 여쭤보셨던 부분인데, 맞습니다. 키워드 프롬프트를 넣으면 그 장면이 배경처럼 이미지에 스며드는 방식입니다. 두 결과를 합쳐서 최종 착시 이미지를 만듭니다.
3단계, VQA 문제 생성입니다. COGNITION 논문에서 언급한 VLM이 특히 약한 유형으로 다섯 가지 문제를 냅니다. 행렬에서 좌표로 과일을 찾거나, 반대로 과일로 좌표를 찾거나, 읽기 순서로 N번째 사물을 고르거나, 8방향 인접 셀을 세거나, 같은 행의 사물을 찾는 문제입니다. 각각 4지선다로 출제됩니다.
마지막으로는 이걸 MSA로 구현해 문제 요청과 정답 제출을 API로 처리합니다.

아직은 MVP 단계라 보완해야할 것이 많지만 평가지표는 설계 원칙을 반영하여 평가는 봇/사람 모두에게 평가하여 오답률을 측정할 예정입니다
